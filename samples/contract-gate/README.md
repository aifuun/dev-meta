# Contract Gate Sample

Reference implementation of the **contract assertion gate** from `docs/06-contract-based-dev.md` §2.8, executed by the `dm-contract-gate` skill (`skills/dm-contract-gate.md`). It mirrors the SHA256 + `contract_verified` pattern of `PochiHide-CoreML-Spike/src/scripts/package_dist.py`, generalized for any project.

## Files

| File | Role |
|------|------|
| `verify_contract.py` | Gate script (stdlib only). `build` records fingerprints; `verify` runs the gate and exits non-zero on failure. |
| `contract.schema.json` | Machine-checkable contract (JSON Schema) — the SSOT the gate verifies against. |
| `contract.json` | Sample contract data conforming to the schema. |
| `MANIFEST.json` | Fingerprint manifest (per-file `sha256` + top-level `contract_verified`). Regenerated by `build`. |

## Three-Gate Mapping (docs/06 §2.8)

- **Gate 1 (pre-implementation)**: before editing code, diff `contract.json` / `contract.schema.json` against the change; treat these as read-only. Breaking change → `dm-adr`.
- **Gate 2 (post-implementation)**: after edits, run `verify` silently; if red, throw the terminal error back and self-repair — never tell the user "done" while red.
- **Gate 3 (delivery)**: on commit/package, run `verify` to confirm `MANIFEST.json` fingerprints + `contract_verified` align.

## Usage

```bash
# 1) Record fingerprints (after editing contract files)
python3 verify_contract.py build --contract-dir .

# 2) Run the gate (non-zero on any failure → throw back for self-repair)
python3 verify_contract.py verify --contract-dir . \
    --contract contract.json --schema contract.schema.json

# CI / git hook: fail the pipeline if exit code != 0
python3 verify_contract.py verify || exit 1
```

On failure the script prints an `[AI-DEBUG-CONTEXT]` structured snapshot (contract dir, `contract_verified`, mismatch list) per `docs/07-observability-driven-dev.md` §3, so the AI localizes in one shot.

## Why `contract_verified`

`contract_verified` is a single boolean the delivery (and the AI) can trust: it is only set `true` by a green `verify` run. `package_dist.py` uses the same field for the CoreML model contract; this sample generalizes it to any parseable contract.

# dm-schedule

## 概述

版本排程 skill，为 Roadmap 版本生成按执行优先级排序的扁平工作包列表。不按周分组 — 执行顺序编码依赖逻辑，实际速度决定完成时间。面向 solo 开发者，定位为战术级 backlog。

## 核心哲学

- **优先级排序的扁平列表**：不设周分组，执行顺序即依赖关系
- **多领域并行**：每版本强制包含 dev / product / marketing / biz / qa 工作包
- **闭环优先**：MVP 阶段优先打通全链路，再考虑功能量级
- **砍功能不砍日期**：延期时通过削减非核心 dev 工作包硬保上线节点

## 工作包 ID 规范

`<领域>-v<X.Y>-<NN>`

| 领域 | 范围 |
|------|------|
| `dev` | 开发与架构 |
| `product` | 产品与 UI 设计 |
| `marketing` | 市场营销与推广 |
| `biz` | 商业化与变现 |
| `qa` | 测试走查 |
| `goal` | 版本里程碑目标 |

## 执行流程

### 1. 收集上下文

询问用户：版本号、上线卡点、量化目标、已知交付物。

### 2. 生成工作包列表

创建 `docs/versions/vX.Y-<slug>/100-schedule.md`。按优先级顺序填充：

1. **基础搭建** — 仓库脚手架、设计 token、品牌资产
2. **核心 UX** — 主用户流程
3. **集成对接** — 第三方服务、支付、部署
4. **质量走查** — 跨设备测试、bug 修复
5. **正式发布** — 商店提交、营销推广

### 3. 定义红线

四铁律默认保留，除非用户显式覆盖。

### 4. 确认保存

# AI 协作三支柱 + 架构设计总纲 — 索引卡（非全文，纯指针）

> 本卡为 `dm-arch-design` 的按需参考索引。应用架构设计时，若需精确条款，按下方路径读 `docs/` 原文；本卡只列**关键条款锚点**，避免与权威文档重复定义。

## 06 契约式开发（Contract-Based Dev）— `docs/06-contract-based-dev.md`

- **§8 契约只读纪律与断言门禁**（AI 协作核心）：写实现前先把 Interface/DTO 作为 Context 喂给 AI；新会话只带契约 SSOT。
- **§3 契约质量基线**：契约须含「正常 / 边界 / 失败」三态，失败面不可省略。
- **§2.1–2.3 契约三层级**：L1 接口/API（基线）、L2 Feature（版本级）、L3 关键行为（测试）；架构边界产出即落入 L1/L2。
- **§4.2 契约状态生命周期**：每条契约**一条一标** `[CURRENT]` / `[PLANNED]` / `[HISTORY]`；S3 翻 `[CURRENT]`。
- **§6 契约资产组织与索引**：单文件 vs 目录的规模阈值、索引门面、归档不删除、落地路径。
- **§7 契约引用与定位纪律**：契约只被引用、不引下游；语义锚点定位；禁写「代码现状」；结构 lint 关版本前必跑。
- **§10 测试职责分层**：核心逻辑需测试，UI/视图不写 TDD（与 08 §2.2 一致）。

## 07 可观测性驱动开发（Observability-Driven Dev）— `docs/07-observability-driven-dev.md`

- **§2.5 写逻辑即写观测**：关键路径须结构化日志；无静默吞错；高开销节点须含 Elapsed + 资源指标。
- **§2.5 出口 Assert**：映射空 / 越界等异常出口须 `assertionFailure`，而非裸 return。
- **§2.6 观测层编号（`O1`–`O3`）**：`L1`–`L3` 专属契约层级；`O1` 断言 / `O2` 埋点 / `O3` 回读。
- **§2.7 负向约束**：热路径禁无条件打点；Release 不得存在运行期日志开关旁路。
- **§3.1 黑匣子诊断**：门禁失败时由结构化日志还原链路；跨模块事件建议带 `trace_id`。
- **§3.2 工作流轨迹**：每观测点须给**判别量**（禁「已到达某步」）；判读表须覆盖全部候选根因；验证落**完整逻辑层**（集成 / E2E），不以单测代替。
- **DoD 9 项**（§7）：原 6 项 + 轨迹可判别 / 轨迹验证在完整逻辑层 / 无旁路与计数同处。

## 08 小版本迭代（Small-Batch Iteration）— `docs/08-small-batch-iteration.md`

- **§1 AI 小批定义**：最小批次 = 单文件重构 / 单函数修复（非人类视角 Sprint）。
- **§2 Commit 级 Micro-Batching（执行粒度）**：改动按性质分契约 / Core / 接入三类（其**顺序与落位归 `docs/02` §6.2 的 Step 0–7**），每类内须拆到**单文件 / 单函数**；每绿灯 Batch **由用户触发 commit**。
- **§2.1 混乱回退**：陷入混乱由用户显式 `git reset --hard` 退回绿灯 Commit，AI 不自发执行破坏性操作。
- **§3 Context Flush / New Session**：小 Task 完成清空对话；新会话只带「最新契约 SSOT + 下一个单点 Task」。

# dm-report

## 概述

阶段性报告生成 skill，从 worklog 中提取指定周期的数据，生成面向 PM / 产品经理的结构化工作报告。聚焦功能交付与里程碑进展，不记录代码或 commit 细节。默认生成周报。

## 职责边界

| 职责 | 归属 |
|------|------|
| 从 `worklog.md` 提取指定周期数据 | ✅ 本 skill |
| 生成面向 PM 的结构化报告（周报 / 月报 / 自定义周期） | ✅ 本 skill |
| 确定报告周期（默认本周一至周日） | ✅ 本 skill |
| 记录工作（写入 worklog） | ❌ 委托 `dm-log` |
| 提交报告 | 委托 `dm-commit` |
| 编造 worklog 中不存在的内容 | ❌ 硬约束（见「关键规则速查」） |

## 核心概念

### 数据来源单一

报告**只**从 `docs/reports/worklog.md` 提取，不编造 worklog 中不存在的内容。worklog 缺失或周期内无记录时，须在报告中**明确说明**，不静默生成看似正常的空报告。

### 面向 PM 的语言

用**功能 / 用户视角**语言，讲清交付了什么能力、进展如何；**不记录** commit hash、代码细节与实现方案。

### 报告六段结构

已完成任务 → 功能交付 → 关键决策与讨论 → 待办进展 → 里程碑 → 下阶段计划。

### 周期与文件名

默认本周一至周日（可指定周 / 月 / 自定义区间）；文件名用当天日期：`docs/reports/weekly-<当天>.md` 或 `docs/reports/report-<当天>.md`。

## 受众

PM / 产品经理。报告语言面向功能交付、业务价值、里程碑进展，避免技术实现细节。

## 执行流程

### 1. 定位 worklog

读取当前项目的 `docs/reports/worklog.md`。若不存在则提示先使用 dm-log 记录工作。

### 2. 确定报告周期

默认本周（周一到周日）。支持：
- 上周、本月、上月
- 自定义日期范围（YYYY-MM-DD 到 YYYY-MM-DD）

### 3. 提取数据

从 worklog 中提取周期内的：
- 每日工作总结
- 详细日志（提取功能级交付物与决策，忽略 commit hash 与实现细节）
- 待办项状态变化
- 里程碑

### 4. 生成报告

按模板输出 6 节报告：已完成任务 → 功能交付 → 关键决策与讨论 → 待办进展 → 里程碑 → 下阶段计划。报告内容不出现具体日期，只罗列完成的任务。

### 5. 保存报告

保存至 `docs/reports/weekly-YYYY-MM-DD.md`（用当天日期），可选提交。

## 使用示例

```
用户: "生成周报"

AI:  1. 读取 docs/reports/worklog.md
     2. 确定周期：2026-07-20（周一）— 2026-07-26（周日）
     3. 提取该周期内的功能交付、关键决策、待办、里程碑（忽略 commit 细节）
     4. 生成面向 PM 的报告：
        - 已完成任务：罗列完成的各项任务（不含日期）
        - 功能交付：交付了哪些能力
        - 关键决策：重要设计决策与讨论
        - 待办进展：状态变化
        - 里程碑：关键节点
        - 下阶段计划：优先级排序
     5. 保存到 docs/reports/weekly-2026-07-26.md（当天日期）
     6. 询问是否提交
```

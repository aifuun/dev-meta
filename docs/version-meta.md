# Version Meta — 版本目录文件规范

本规范定义了每个版本目录下的标准文件结构及其职责分工。

---

## 1. 目录结构

```
docs/versions/vX.Y-<slug>/
├── spec.md              # 做什么：交付特性 + 验收标准 + DoD
├── general-design.md     # 怎么做（宏观）：模块划分 + 数据流 + 关键决策
├── detailed-design.md    # 怎么做（微观）：函数签名 + Schema + API 契约 + 边界异常
└── tasks.md              # 怎么交付：任务拆分 + 执行顺序
```

---

## 2. 各文件职责

| 文件 | 受众 | 回答的问题 | 关键内容 |
|------|------|-----------|---------|
| `spec.md` | PM / QA / Dev | 交付什么能力？怎样算完成？ | 交付特性描述、功能验收标准、架构验收标准、DoD |
| `general-design.md` | 架构师 / Dev | 模块怎么划分？数据怎么流？ | 模块关系图、数据流方向、关键技术决策与原因 |
| `detailed-design.md` | Dev | 边界情况怎么处理？具体怎么落代码？ | 函数签名、Schema、API 契约、异常路径策略 |
| `tasks.md` | Dev / PM | 分几步做？先后顺序？ | 任务拆分列表、依赖关系、预估执行顺序 |

---

## 3. 设计为何分两层（general + detailed）

### 3.1 AI 辅助开发视角

两层设计文件与 AI 协作的 workflow：

```
1. 人定 general-design → 确认模块划分、数据流向、关键决策
2. general-design 作为 prompt → AI 生成 detailed-design
3. detailed-design 确认后 → AI 直接落代码
```

### 3.2 分层收益

| | general-design | detailed-design |
|------|:---:|:---:|
| **上下文窗口** | 短，聚焦架构决策 | 长，聚焦落地细节 |
| **迭代频率** | 低（架构一旦定下很少改）| 高（函数签名、边界条件反复调）|
| **审核方式** | 人审架构合理性 | AI 生成，人审具体实现 |
| **信息密度** | 每个模块一句话说清职责 | 每个函数完整签名与注释 |

### 3.3 各自内容边界

**general-design.md** 包含：
- 模块拆分与职责一句话描述
- 模块间数据流方向图（文字描述即可）
- 关键架构决策及理由（为什么选 A 不选 B）
- 与现有版本的继承/变更关系

**general-design.md 不包含**：
- 函数签名
- 完整 API 参数列表
- 伪代码
- 具体异常处理策略

**detailed-design.md** 包含：
- 每个新增/修改函数的完整签名（参数 + 返回值 + 异步与否）
- 数据结构 / Schema 定义（如 IndexedDB object store keyPath）
- API 调用顺序与前置条件
- 边界情况与异常路径策略（如配额满、隐私模式、并发冲突）
- 风险与缓解措施

## 4. spec.md 内容结构

```
# VX.Y 特性规格

## 1. 交付特性
（自然语言段落，描述本版本交付了哪些用户/系统能力，不带文件路径）

## 2. 功能验收标准
（表格：验收项 | 验证方法 | 通过标准）

## 3. 架构验收标准
（表格：验收项 | 通过标准）

## 4. DoD (Definition of Done)
（勾选框清单）
```

---

## 5. general-design.md 内容结构

```
# VX.Y 概要设计

## 1. 背景与目标
（本版本解决什么问题，上一版本基线是什么）

## 2. 模块划分
（新增/修改哪些模块，各模块一句话职责）

## 3. 数据流
（模块间调用关系与数据流向）

## 4. 关键决策
（影响架构的选择及理由）

## 5. 与现有版本的继承关系
（表格：现有模块 → 本版本变更）
```

---

## 6. detailed-design.md 内容结构

```
# VX.Y 详细设计

## 1. 模块设计
（每个模块的函数签名、入参、返回值、调用时机）

## 2. 数据 Schema
（存储结构、key 命名规则、索引设计）

## 3. API 契约
（模块间调用顺序、前置条件、返回值约定）

## 4. 异常与边界
（配额不足、隐私模式、并发、大数据量等场景的处理策略）

## 5. 风险与缓解
（表格：风险 | 影响 | 缓解措施）
```

---

## 7. tasks.md 内容结构

```
# VX.Y 任务拆分

## 1. 任务列表
（表格：序号 | 任务 | 涉及文件 | 依赖 | 预估）

## 2. 执行顺序
（文字描述推荐顺序）
```

---

## 8. 反模式

以下内容不应出现在对应文件中：

| 不要放在… | 内容 | 应放在 |
|-----------|------|--------|
| spec.md | 具体文件路径清单 | detailed-design.md |
| general-design.md | 函数签名 | detailed-design.md |
| detailed-design.md | 模块职责一句话描述（冗余） | general-design.md |
| tasks.md | 功能验收标准 | spec.md |
| spec.md | 数据 Schema | detailed-design.md |
